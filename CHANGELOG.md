# Changelog

## 1.0.0 — готовый язык

- tests/fuzz/fuzz.js: генератор случайных wasm-модулей (i32/i64 режимы,
  память, таблицы, call_indirect, select, if/else, блоки с br_if, вызовы) →
  `ribo roundtrip` на каждом. 1100 модулей зелёные, включая трап-классы.
- **Фаззер поймал настоящий баг:** лифтер перепутал i32.shr_s (0x75) и
  i32.shr_u (0x76) — лил логический ISHR вместо арифметического ISAR
  (и симметрично для i64). Поймано модулем seed 1166: оригинал -1,
  лифт 65535. Эмиттер был правильным — только лифт. Урок записан:
  паритет проверяется фаззером, не глазами.
- build_web.ps1 больше не ломает PATH вызывающего: санитизация в
  try/finally (урок: `.\script.ps1` выполняется в текущем скоупе).
- LLM.md: выверен по коду — полная таблица фолт-контрактов, `ribo test`
  в workflow, TABLE/TELEM/DATA/CALLI задокументированы.
- Страница: примеры dispatch (CALLI) и data (сегменты), Ctrl+Enter = запуск,
  версия в шапке. README: как запустить CLI, фаззер и статический хостинг.

## 0.8.0 — таблицы, CALLI, data-сегменты (замыкаем wasm MVP)

- Новые декларации: `TABLE t min[,max]`, `TELEM off f1,f2` (цели — функции
  или НЕ-void импорты), `DATA off hex` (байты в память при инстанцировании,
  лимит 200 байт на строку под 511-байтный лимит линии — лифтер режет сам).
- Новый опкод `CALLI rI r1,r2`: вызов TABLE[i32(rI)] с аргументами, результат
  в r0. Три новых фолта с точными текстами: "indirect call index out of
  bounds", "indirect call to uninitialized table entry", "indirect call type
  mismatch" (арность; void-импорт в таблице — тоже mismatch, паритет с V8).
- Чекер: CALLI читает регистр индекса + аргументы, пишет r0; модульные
  доказательства: DATA⊂MEM, TELEM⊂TABLE, CALLI требует TABLE.
- Эмиттер: секции 4 (table), 9 (elem, смежные TELEM сливаются в сегменты),
  11 (data); сигнатуры call_indirect (i64×n)->i64 по используемым арностям.
- Лифтер: секции 4/9/11 (только active, table/mem 0, константные оффсеты;
  длинные DATA режутся на строки ≤ 200 байт), call_indirect 0x11 → CALLI.
- Урок: TELEM-имена должны идти через func_name лифтера (функции называются
  по экспортам, не f0/f1) — иначе "undefined func in TELEM".
- fault_class в verify/roundtrip обобщён: любой "out of bounds" → oob
  (V8 пишет "out of bounds table access" для таблиц).
- Фикстура indirect.wasm (call_indirect + elem + data): roundtrip-match по
  dispatch 0/1/2/9, memrd, inc — включая оба трапа (uninitialized, oob).
- Веб: ядро пересобрано (122 КБ), примеры dispatch (CALLI) и data на странице;
  дифф-панель подтверждает паритет трапов в браузере.

## 0.7.0 — полнота MVP-арифметики

- Новые опкоды (последний численный пробел до 1.0): F2IU/F2LU/D2IU/D2LU
  (беззнаковые транкации, трап на NaN/<= -1/>= 2^N), ICLZ/ICTZ/IPOP и
  LCLZ/LCTZ/LPOP (битовый подсчёт, без трапов), IROTL/IROTR/LROTL/LROTR
  (ротации; счётчик МАСКИРУЕТСЯ как в wasm — сознательное отличие от сдвигов,
  чтобы лифт wasm-ротаций был 1:1).
- Лифтер: исправлен баг паритета — wasm маскирует счётчик сдвига, а ISHL/…
  трапают за пределами 0..31/63; теперь при лифте сдвига генерируется
  явный IAND/LAND маски. Поймано фикстурой shiftmask.wasm: smask(1,33)=2.
- Лифтер поддерживает 0x67-0x69/0x79-0x7B (clz/ctz/popcnt), 0x77/0x78/
  0x89/0x8A (rot), 0xA9/0xAB/0xAF/0xB1 (unsigned trunc) — новые фикстуры
  shiftmask.wasm и bits.wasm проходят roundtrip.
- Веб-оболочка: кнопка «Дифф ↔ V8» — интерпретатор и пониженный wasm
  исполняются на одной странице, сравниваются канонические строки, трапы
  тоже сравниваются (оба пути обязаны трапать вместе). Найден и исправлен
  баг оболочки: обёртки принимают i64-ячейки, float-аргументы передаются
  битовым паттерном (BigInt), а не Number.
- Встроенный браузер DSH оживлён (установлен бинарь electron в профиль) —
  оболочка проверена в нём: add/fact/circle/memsum MATCH, трап div0 MATCH,
  rots с ICLZ/ICTZ/IPOP/IROTL MATCH.

## 0.6.0 — браузер: ядро исполняется на странице

- web/wasm/: freestanding-сборка ядра clang --target=wasm32, без emscripten
  и без libc. Свой shim (web/wasm/shim.c): K&R malloc поверх memory.grow,
  ASCII ctype/string, snprintf-lite (%s %.*s %d %u %lld %llu %x %a),
  точный hex-float strtod; decimal strtod — best-effort (CLI остаётся
  эталоном парсинга литералов). Файловые API собираются, но fopen-заглушка
  всегда возвращает NULL — хост использует ribo_compile_text /
  ribo_emit_wasm_mem / ribo_wasm_lift_mem.
- Рефакторинг interp.c: setjmp/longjmp убраны в пользу sticky-флага
  faulted (у wasm нет setjmp). Пойман и исправлен регрессионный краш:
  после fault() исполнение продолжалось до аппаратного деления на ноль —
  теперь все fault-сайты в горячих кейсах выходят через break, OP_CALL
  защищён от записи за границу фреймов. Урок: fault, который «не
  возвращается», должен это доказывать структурой, а не конвенцией.
- web/api.c: буферный ABI (ribo_in/ribo_args/ribo_out/ribo_wasmout +
  ribo_do_check/run/lower/lift). web/index.html: редактор, примеры,
  запуск, скачивание .wasm, drag&drop-лифт .wasm → .rna.
- web/serve.js: статический сервер без зависимостей (node serve.js 8086).
- Проверено в живом браузере: check/run для add/fact/circle/memsum;
  f64 биты совпали с CLI-эталоном; web\ribo.wasm = 106 КБ.
- build_web.ps1: clang wasm32; PATH чистится от битого wasm-opt из
  каталога Node (иначе clang падает при линковке).

## 0.5.0 — лифтер: wasm → .rna, круг замкнут

- lift.c: бинарь wasm → текст .rna. Стек операндов поднимается в регистры
  статическим моделированием высоты стека (слот k = регистр 8+nlocals+k;
  r0..r7 — скретч, туда падает результат CALL). Структурный контроль
  (block/loop/if/else/br/br_if/br_table/select) опускается в LABEL/JMP/JZ/
  JNZ; ветка в блок с результатом сначала MOV-ит вершину стека в базовый
  слот цели.
- wasm-опкоды сами типизированы — типовой стек не нужен, префикс I/L/F/D
  выбирается прямо из опкода.
- Все чтения бинаря bounds-checked; неподдержанное (таблицы, data-сегменты,
  call_indirect, multi-value, unsigned-транкации, rotl/rotr/clz/ctz/popcnt)
  — чистая ошибка "reserved for 1.0", никогда не падение.
- Новая декларация языка GINIT name lit: ненулевой инициализатор GLOB
  (у wasm-глобалов есть инициализаторы, без GINIT честный лифт невозможен).
  Эмиттер теперь пишет инициализаторы глобалов из bits.
- ribo lift + ribo roundtrip: lift → компиляция .rna → обратная эмиссия →
  оба wasm гоняются в V8 и сравниваются канонически.
- Фикстуры tests/fixtures/build_fixtures.js: ручная сборка "чужих" модулей
  (fact_iter, collatz, sum_arr) — лифтер тестируется на wasm, который НЕ
  эмитировал сам Ribosome (свой dispatch-loop для лифтера патологичен:
  259 локалей > бюджета регистров, это осознанный предел).

Урок: в ribo_wasm_parse оффсеты тел функций считались как `r.p - w->bytes`,
где r ходит по ОРИГИНАЛУ, а w->bytes — копия: разность двух аллокаций = UB.
Симптом — "stack underflow at IOR" в пустом месте, зависящий от раскладки
кучи. Оффсеты считаем по тому же буферу, по которому ходит reader.

Пропущен 0.4: эмиттер 0.3 сразу покрыл float/память/глобалы.

## 0.3.0 — прямая эмиссия wasm + дифференциал против V8

Язык стал настоящим: .rna исполняется движком браузера.

- emit_wasm.c: бинарь .wasm пишется напрямую, без clang (решение D5).
  Регистры — i64-локали wasm, I/F-опкоды оборачиваются wrap/reinterpret на
  месте использования. Goto-поток кодируется диспетчер-циклом: вложенный
  блок на инструкцию + br_table по pc (O(1) переход, без релооператора).
- Фолты маппятся на wasm-трапы: деление и транкации трапают нативно,
  сдвиги получают явную проверку счётчика (wasm маскирует, мы — нет),
  TRAP → unreachable.
- Экспорт — тонкие обёртки с объявленным типом результата; параметры
  передаются как i64-ячейки (BigInt в JS). Память экспортируется как
  "memory".
- tests/wasm/run.js + `ribo verify`: канонизация результата (i32/i64
  десятично, f32/f64 — сырые биты hex) и классов трап (div0, divovf, oob,
  trunc, stack, trap). verify сам экспортирует проверяемую функцию.
- Проверено: add (включая i32-wraparound 2^31-1 + 1), fact (i64-рекурсия),
  circle (f64 бит-в-бит), memsum (память), torture (ILTU/сдвиги регистром/
  глобалы/CALL), fmin (-0.0 семантика), fill (void), трапы div0 и
  shift-guard — всё match между интерпретатором и V8.

Урок: verify вызывает node через system() с редиректом в файл, а не через
pipe — так работает и в песочнице Windows без named pipes.

## 0.2.0 — парсер, чекер, эталонный интерпретатор

Первая работающая версия. `ribo check/run/test` исполняют контракт LLM.md
целиком — включая float и линейную память (по roadmap они планировались на
0.4, но в интерпретаторе на C они оказались дешёвыми; сложность ждёт нас в
эмиттере wasm).

- parse.c: строгие 3 поля, `_`, repair (дописывает хвостовые `_`), BOM
  пропускается, все ошибки с line/line_text. Ссылки на метки/функции/глобалы
  разрешаются фиксапами после разбора.
- check.c: доказательство инициализации регистров на всех путях (dataflow по
  графу переходов), RET-покрытие (падение в END — ошибка), арности CALL,
  RET по сигнатуре, MEM для памятных опкодов.
- interp.c: все 127 опкодов. Явный кадровый стек в куче (2 МБ потолок при
  глубине 1024), бюджет шагов из RiboLimits, линейная память с проверкой
  границ и MGROW, импорты через RiboIO capabilities, wasm-семантика
  MIN/MAX (NaN, ±0) и трапующие F2I/D2I.
- cli.c: `check` (с --json по контракту агента), `run`, `test` (CSV).
  Аргументы с '.', 'e', inf/nan трактуются как f64-биты.
- Проверено на examples/: add, fact (i64-рекурсия), circle (f64), fill и
  memsum (память). Шесть классов ошибок возвращают точные тексты контракта.

Урок: PowerShell `Out-File -Encoding utf8` пишет BOM — парсер обязан его
пропускать, иначе первая строка файла не распознаётся.

## 0.1.0 — спецификация и скелет

Проект открыт. Код не написан — написан контракт.

- LLM.md: полный контракт языка `.rna`. Один 64-битный регистровый класс
  (урок раздвоения rN/wN из Codons), префиксы I/L/F/D, линейная память,
  глобалы, импорты-capabilities, 8 аргументов.
- include/ribo.h: публичный API. Все лимиты — конфигурация запуска
  (RiboLimits), а не #define (урок BIO_EXECUTION_LIMIT).
- docs/architecture.md: конвейер parse/interpret/emit/lift, план подъёма
  стека wasm в регистры.
- docs/design-decisions.md: D1–D8 — что наследуем от Codons и что выкидываем
  (JIT, строки, CLI-центричность).
- Эмиссия wasm — прямая, без clang (решение D5).
- examples/: эталонные программы, фиксирующие синтаксис до реализации.
