# Архитектура Ribosome

## Конвейер

```
 .rna ──parse──> RiboModule ──emit──> .wasm ──> движок браузера / Node
                    │                                │
                    └──interpret──> result ◄──diff───┘
 .wasm ──lift──> RiboModule (обратное направление, 0.3)
```

Один внутренний формат (`RiboModule`), четыре направления: parse, interpret,
emit, lift. Верификация — всегда дифференциальная: два пути исполнения одного
модуля обязаны совпасть побитово (результат, фолт, потраченные шаги не
обязаны — семантика обязана).

## Компоненты ядра (src/, чистый C11, без зависимостей)

| Файл | Ответственность |
|---|---|
| `parse.c` | .rna → RiboModule. Строгие 3 поля, ошибки с line/line_text, режим repair |
| `check.c` | статические доказательства: инициализация регистров на всех путях, арности, сигнатуры, типы RET |
| `interp.c` | эталонный интерпретатор. Единственный источник истины о семантике |
| `emit_wasm.c` | RiboModule → бинарь .wasm напрямую (без clang), валидация структуры модуля |
| `lift.c` | .wasm → RiboModule (0.3+): подъём стека в регистры, структурного control flow в LABEL/JMP |
| `fault.c` | коды и тексты фолтов, единые для всех путей исполнения |
| `cli.c` | ribo check/run/lower/verify/lift/roundtrip, JSON-режим |

Ядро собирается двумя способами: нативный CLI (MSVC/clang/gcc) и
`clang --target=wasm32-unknown-unknown -nostdlib` для веб-оболочки.

## RiboModule

Скомпилированный модуль: таблица функций (арность, тип результата, массив
инструкций, карта меток), таблица импортов/экспортов, глобалы, декларация
памяти. Неизменяем после parse+check. Интерпретатор и эмиттер читают один и
тот же модуль — расхождение бэкендов невозможно «по разногласию парсеров».

## Семантика исполнения

- Кадр вызова: 256 регистров r0..r255 (64-бит ячейки), аргументы в r0..r(N-1).
- Префикс опкода интерпретирует биты: I — младшие 32 (знаково), L — все 64,
  F — binary32 в младших 32, D — binary64. MOV копирует биты вслепую.
- Линейная память: байтовый массив, растёт страницами по 64 KiB через MGROW;
  границы проверяются на каждом доступе, промах — фолт.
- Фолты — часть контракта: division by zero / overflow, shift count вне
  диапазона, memory out of bounds, trunc NaN/overflow, TRAP, невыданный
  IMPORT. Тексты едины для интерпретатора и для trap-маппинга в wasm.
- Бюджет шагов: декремент на инструкцию; лимит — конфигурация запуска
  (RiboLimits), дефолт 10 000 000. Исчерпание — фолт, не UB.

## Подъём wasm → .rna (lift, 0.3)

- Каждая wasm-функция → FUNC. Стек операндов лифтуется в регистры статическим
  моделированием глубины стека (wasm структурен: глубина известна в каждой
  точке). Слот стека k → регистр r(k + арность).
- block/loop/if/br/br_if/br_table → LABEL/JMP/JZ/JNZ. Для br_table — каскад
  сравнений (0.3), нативная таблица переходов — позже.
- local.get/set/tee → MOV между регистрами; локалы wasm → регистры после
  аргументов и слотов стека.
- Импорты/экспорты/глобалы/память → IMPORT/EXPORT/GLOB/MEM напрямую.
- Критерий корректности: roundtrip — lift(m) → lower → дифференциал против m
  на общих входах. Корпус Codons-подобных примеров + реальные модули.

## Веб-оболочка (web/, 0.4)

Ядро, собранное в wasm, плюс статичная страница: редактор .rna, кнопки
check/run/lower, drag&drop .wasm для lift, панель дифференциала (оригинал vs
пересборка на одних входах, подсветка расхождений). Без сервера: открывается
как файл или с любого статического хостинга.

## Тестирование

- `tests/cases/*.csv` — смысловые кейсы в стиле Codons (arg…,expected).
- `tests/diff_*.py` — дифференциальные прогоны интерпретатор vs Node/V8.
- Фаззинг: генератор случайных .rna в границах грамматики, прогон обоих путей,
  сравнение результатов и фолтов.
