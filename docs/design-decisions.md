# Решения по дизайну Ribosome

Документ фиксирует, что взято из Codons, что выкинуто и почему. Каждое решение
привязано к уроку или к требованию домена. Codons (S:\Codons) — эталон и
референс; он не изменяется.

## D1. Отдельный проект, а не надстройки Codons

Codons — закрытый мир: 80 опкодов, контракт на 271 строку, его ценность в
завершённости. Домен Ribosome (wasm) требует float и линейной памяти в ядре —
для Codons это были бы надстройки, размывающие его границу. Вывод: не растить
один язык, а строить семейство законченных маленьких. Ribosome — второй из них.

## D2. Браузер — единственная платформа, wasm — единственный бэкенд

Следствия:
- **Нет собственного JIT.** Урок Codons 0.12 (RDI, callee-saved, порча кучи
  при -O3) — самый дорогой класс багов нативного кодгена. Движок браузера
  JIT-компилирует wasm лучше нас; исполнитель не пишется вообще.
- **Оракул верификации внешний.** У Codons паритет «интерпретатор ↔ JIT» —
  внутренний. У Ribosome дифференциал против V8/wasmtime — сильнее и дешевле.
- **Песочница бесплатно.** Wasm в вкладке уже изолирован.

## D3. Один 64-битный регистровый класс

Главный архитектурный шрам Codons — раздвоение `rN` (i32) / `wN` (i64) с
ручными WIDEN/NARROW: удвоение опкодов, рантайм-фолты NARROW, путаница модели.
В Ribosome регистры `r0..r255` — 64-битные ячейки сырых бит; префикс опкода
(I/L/F/D) задаёт интерпретацию. Конверсии — явные опкоды. Это решение принято
до первой строки кода, потому что потом оно тектоническое.

## D4. Опкоды выводятся из wasm MVP, а не выдумываются

Размер ядра — не вкусовщина: берём набор инструкций wasm MVP, кластеризуем,
выбираем минимальное покрытие. Правила:
- 1:1 с wasm там, где это возможно (лifter должен быть механическим);
- сахар запрещён (нет INEG для целых — в wasm его нет; есть FNEG/DNEG — в wasm есть);
- бюджет опкодов осознанно выше, чем у Codons (~125 против ~80): это цена
  домена, фиксируем её, а не прячем.
- зарезервировано на потом: CALLI/таблицы, CLZ/CTZ/POPCNT, unsigned-транкации
  (F2IU и т.п.), ROTL/ROTR.

## D5. Прямая эмиссия wasm-бинаря, без clang

Codons emit-wasm генерирует C и зовёт clang. Для Ribosome wasm — родная цель:
бинарный формат прост, зависимость от внешнего тулчейна противоречит
«всё живёт в браузере». Эмиттер пишет .wasm сам. Побочный бонус: тот же
эмиттер, собранный в wasm, работает на странице.

## D6. Все лимиты — конфигурация рантайма

`BIO_EXECUTION_LIMIT` как #define в Codons блокирует целые сценарии (игровой
цикл) на уровне заголовочника. В Ribosome лимиты (шаги, глубина, страницы
памяти) — поля конфигура запуска с дефолтами из LLM.md.

## D7. Capability-модель для импортов

IMPORT в wasm — это ровно BioIO из Codons: хост явно выдаёт каналы, программа
без канала падает с точной ошибкой. Порядок проверок (capability → валидность →
бюджет → вызов) наследуется как есть.

## D8. Дисциплина текста без изменений

3 поля на строку, `_`, запрет пробела после запятой, точные ошибки с
`line_text`, `--repair`-мышление, LLM.md как артефакт первого класса. Это то,
что делает язык пригодным для ИИ — не трогаем.

## Что осознанно НЕ в 0.1

- Лифтер (wasm → .rna): сначала язык + интерпретатор + эмиттер + дифференциал.
- Веб-оболочка: после работающего CLI-ядра.
- Потоки, SIMD, GC, reference types: за пределами MVP, не планируем, пока
  MVP-круг не замкнётся с доказательством.
